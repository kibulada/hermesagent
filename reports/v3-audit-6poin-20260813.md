## POIN 2 — Flow tiap Unit

### Rajal (pasien → pulang)
- **v1**: registrasi → antrean → triase perawat → initial assessment → SOAP → order penunjang/resep → verifikasi → billing → kasir. Langkah tersebar di banyak halaman/route.
- **v3**: registrasi stepper (`/registrasi/pasien`) → antrean station (`/perawat/station`) → NurseWorkspace (TTV, asesmen, implementasi) → `/dokter/worklist` → **DoctorWorkspacePage = 1 halaman, 7 tab**: Asesmen Awal Medis, SOAP/CPPT, Resep, Order Penunjang, Tindak Lanjut (Care Plan), Laporan Operasi, Asesmen Spesialistik (Diagnostik/Mata/Kebidanan/Anak/GDS/Geriatri/MESO) → charge otomatis ke episodeCharges → BillingPage → kasir.
- **Gate**: finish dokter butuh care plan; finish pasien butuh TTD (configurable; hard-gate belum aktif).

### IGD
- **v1**: triase medis → order ruang → initial assessment ER → SOAP → obat → disposisi.
- **v3**: `/igd/board` (triase realtime) → registrasi → `/igd/triase` (form triage-igd **disposisi enum**: rawat-inap/jalan/observasi/rujuk/pulang-paksa/meninggal) → **`/igd/order-ruang` = SPRI langsung terbit + episode ranap dibuat + masuk panel "Menunggu Penempatan" bed board** → verifikasi pasien temporary + **merge ke MR permanen** → cetak gelang barcode ZPL + kartu antrian ZPL.

### Ranap (SPRI → discharge)
- **v1**: SPRI → admisi → bed board → visite → SOAP/resep → discharge planning → pulang.
- **v3**: **SPRI dibuat di CarePlanSection (tab "Tindak Lanjut" type=inpatient)** → admisi via `/ranap/admisi` (atau order-ruang dari IGD) → `/ranap/board` (board per bangsal, realtime) → **visite harian** (`inpatient_visites`, masuk episodeCharges, tarif resolve) → SOAP + resep + **konsul ambil-alih (take-care)** → transfer bed (ledger `bed_transfers`) → discharge planning form (wajib dischargeCondition) → **discharge: bebas-kan bed → CLEANING + return SEP (updTglPlg) otomatis** → resume medis WYSIWYG → sensus RL server-side.

### Konsul (lintas unit)
- **v1**: konsultasi-dokter terpisah per role, halaman sendiri.
- **v3**: `/dokter/konsul` (KonsulPage) — worklist care-plan type=consult, jawab inline (respondConsult), + Konsul ambil-alih di ranap. Satu titik untuk semua unit.

### Penunjang (lab/rad)
- **v1**: order → spesimen → kerja → hasil → ekspertise → verifikasi.
- **v3**: order multi-item qty-aware → **spesimen barcode + chain-of-custody (collect/received/rejected/discarded)** → hasil terstruktur (CBC analit / finding-impression) → **deteksi nilai kritis otomatis (14 analit SNARS) + alert + acknowledge** → ekspertise (assignment dokter) → verifikasi + stempel + kode-verifikasi offline + DRAFT watermark → cetak TTD.

### Kasir
- **v1**: bikin invoice manual → edit harga → split coverage.
- **v3**: BillingPage tarik charge otomatis (obat/lab/rad/MCU/operasi/visite/akomodasi) → coverage matrix self/BPJS/asuransi → split → editable price + item discount + global discount → void → reversal anti tagih-ganda (ALREADY_BILLED guard) → kwitansi → outbox saga → Odoo (monitoring + retry idempoten).

### Farmasi
- **v1**: 1 halaman generik.
- **v3**: ordered → confirmed → paid → dispense (7-benar wajib) → completed; telaah/verifikasi resep (6 concern whitelist), retur obat (stok + invoice draft), FEFO batch + kadaluarsa, label etiket, rekap penyerahan, OTC sale, antrean TV + TTS.

## POIN 3 — Penilaian UX Flow v3

### ✅ Bagus
1. **Satu workspace per peran** — dokumen EMR dokter jadi 1 halaman tab; tidak pindah-pindah route seperti v1 (60+ sub-folder).
2. **Konsul & visite inline** — tanpa keluar episode.
3. **Charge otomatis** — perintah penunjang/visite/operasi langsung masuk rincian tagihan (v1: manual rekap).
4. **Alur farmasi 7-benar + status jelas** — tiap transisi punya guard + pesan DomainError Bahasa Indonesia yang terbaca.
5. **Real-time (SSE) + TV + TTS** — antrean poli/farmasi push real-time, panggilan suara id-ID.
6. **Feedback visibilitas stok**: dispense stok-0 kini terlihat (FB #162), retur restore stok.
7. **Cetak modern**: gelang ZPL, kartu antrian, SPRI, resume WYSIWYG, SEP — tanpa lib eksternal.
8. **Konfirmasi destruktif**: void invoice, batal resep, discharge — semua ada Popconfirm/guard.

### ⚠️ Kurang / risiko UX
1. **Login masih dev-mode dulu** — sekarang username/password + forgot/reset sudah ada (mode reset-link, token dikembalikan ke layar karena SMTP belum siap; prod perlu SMTP). JANGAN salah sebut "belum ada" — ada tapi belum ada email.
2. **Stub/placeholder tersisa** — DICOM terkompresi masih unduh (cornerstone3D baru JPEG/JPEG2000/JPEG-LS/RLE; belum semua transfer syntax), EKG waveform-strip belum (hanya interpretasi skalar), VClaim/Antrean/SatuSehat/Dukcapil mock-first.
3. **7 leaf masih di STUB_LEAVES** — `/ranap/clinical-pathway`, `/laporan/flow-dashboard`, `/rt/*` (4) → semua sudah di-route nyata di App.tsx (cek `REAL_LEAVES` vs `STUB_LEAVES` → `STUB_LEAVES` = 0 item ter-hitung, karena `REAL_LEAVES` berisi route yang sudah ada; jangan percaya label "stub" di PARITY-DEPTH-GAPS yang basi). Verifikasi: node script → 0 stub.
4. **Workspace tab bisa overload** — DoctorWorkspace 7 tab + sub-tab spesialistik 8; layar kecil padat.
5. **TTD hard-gate belum aktif** — default catat tanpa blokir (keputusan produk pending).
6. **Initial assessment dokter = tab, bukan step wajib** — bisa terlewat tanpa urutan terstruktur.

## POIN 5 — Potensi yang Harusnya Ada di v3

### Blocker fungsional (wajib, berisiko uang/regulasi)
1. **Guard cek stok saat dispense/OTC** — `deductFefo` + `applyStockMovement` potong stok tanpa cek `qtyOnHand` cukup → stok bisa minus (overdraw). v1 punya cek; v3 belum.
2. **Guard UNPAID invoice saat discharge** — `dischargeEpisode` tidak cek invoice draft belum lunas → pasien pulang tanpa bayar. Risiko finansial.
3. **Guard duplikasi visite harian** — `recordVisite` tak ada unique `(episodeId, doctorId, visitDate)` → klik ganda = tagihan ganda.
4. **Guard re-issue SEP** — `sep.service.issue` tidak cek `bpjsSepNo` sudah terisi → bisa SEP ganda di VClaim (duplicate claim).
5. **Guard admisi ranap** — `admitToInpatient` cek episode inpatient open SUDAH ADA (RANAP_ALREADY_ADMITTED) — tapi guard Rajal baru cek unit SAMA (RAJAL_ALREADY_OPEN_SAME_UNIT), beda poli hari sama masih bisa daftar (bisa dianggap by-design atau gap — verifikasi kebijakan).
6. **Pendaftaran Rajal ganda beda poli** — guard hanya per unitId; pasien di poli A bisa daftar poli B hari sama. Keputusan produk.

### Depth yang masih tipis (SHALLOW → FULL)
7. **DoctorExternal enrolment** — telemedicine ada, registrasi dokter eksternal nol.
8. **company-partner vendor/contractor** — v3 hanya insurer.
9. **MCU group registration** — MCU jadi support-order 1-form; v1 punya alur registrasi grup + verifikasi + manajemen.
10. **Surgery prescription (resep OK spesifik)** — pakai farmasi OK generik.
11. **EKG waveform-strip canvas** — butuh feed alat.
12. **INA-CBG grouper resmi** — sekarang indikatif (biner Kemenkes = follow-up).
13. **VClaim/Antrean WS/SatuSehat/Dukcapil riil** — semua mock-first, butuh kredensial prod.
14. **DICOM lengkap** (MPR, measurement, PACS query/retrieve, semua transfer syntax).
15. **LIS MLLP bridge** — ingest sudah, jembatan analyzer TCP belum.
16. **TTD hard-gate** — keputusan produk.
